## フェーズ粒度の方針（レビュー予算）

> 粒度は「実装者の都合」ではなく「**人間が1サイクルで追えるレビュー量**」に合わせる。迷ったら小さく。

- 較正レベル: **M（標準）** ← S / M / L から選ぶ。ユーザーに合わせて調整可。
  - **S（小）**: 1関数 / 1ふるまい・≤ ~80行・レビュー5分（細かく追いたい・学習中）
  - **M（標準）**: 1機能スライス・≤ ~200行・レビュー10〜15分
  - **L（大）**: 複数機能・≤ ~500行・レビュー30分（設計を任せたい上級者）
- 1サイクル（=1 PR）の単位: spec の「完了の目安」1つに対応する**縦スライス1本**。
- 新概念は1つ / 新規テスト 1〜3。超えそうなら**フェーズを分割**する。
- 着手ゲートで、差分規模が較正レベルに収まるかを一言確認する。

## 開発モード（PoC / 製品）

> 較正レベル（S/M/L）が「**1サイクルの量**」の軸なのに対し、開発モードは「**品質ゲートの厳しさ**」の軸。
> ゲートが厳しすぎて PoC が完成しないまま検証に入れない、という事態を避けるために明示する。

- モード: **PoC** ← PoC / 製品 から選ぶ。Phase 単位で切り替えてよい。
- **PoC モードは「テストを書かない」ではない。「テストの置き場所を spec 層1（システム全体 I/O・モジュール間インターフェース）に集中させる」モード。** 境界さえ固まっていれば、少ないテストで振る舞いを守れる（`agent_docs/common/test_policy.md`）。
- **卒業**: PoC が目的を果たしたら「製品モード切替 PR」を立て、不足しているテスト・lint 警告・カバレッジを補充してから製品モードへ移す。

| 項目 | PoC モード | 製品モード |
|---|---|---|
| テストを置く場所 | **spec 層1 の境界のみ**（内部関数のテストは書かない） | 層1 ＋ 層2（関数レベル） |
| 1 PR の新規テスト | **0〜2**（境界が変わらない限り増やさない） | 1〜3 |
| レッド確認 | **境界に触る PR のみ必須**（内部だけの PR は既存テストが緑で可） | 毎サイクル必須 |
| カバレッジ | 測るが**門にしない** | PR 前より低下させない |
| lint | **format ＋ error のみ門**（warning は非門） | 警告ゼロ |
| CI | build ＋ 境界テスト ＋ format（**目標3分以内**） | build ＋ 全テスト ＋ lint ＋ 静的解析 |
| ADR | **不可逆な判断のみ** | 計画からの逸脱すべて |
