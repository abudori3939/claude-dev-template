# review_checklist.md — 出図前・発注前チェックリスト（KiCad）

> PR レビュー・ユーザー確認に出す前に、該当セクションの全項目を確認する。
> ハードウェアは製造後の修正コストが桁違いに高い。**「発注前」セクションは PR マージとは別の最終ゲート**であり、必ず人間と一緒に通す。
> プロジェクト固有の必須項目があれば、この項目に追記して使う。

## 0. リポジトリ衛生（全 PR 共通。Windows / Ubuntu 混在対策）

**この節は目視で追わない。** 下記1項目を実行すれば、CRLF・一時ファイル・絶対パス・KiCad バージョン混在の4点は機械が判定する（CI でも同じコマンドが走る）。

- [ ] `python scripts/check_repo_hygiene.py --expect-version <固定値>` が OK か（＝ CI の衛生チェックが緑か）
  - NG の場合の直し方はスクリプトの出力メッセージに従う（`.gitattributes` 修正＋`git add --renormalize .` / `git rm --cached` / `${KIPRJMOD}` 相対化 / KiCad バージョンを揃える）
- [ ] 参照しているファイル名の大文字小文字が実ファイルと一致しているか（Ubuntu では区別される。スクリプトでは検出できないため目視）

## 1. 回路図 PR（spec との一致 = テスト緑に相当）

- [ ] 接続テスト（ネットリスト pytest）が全緑か
- [ ] ERC 警告ゼロか（抑制した項目は理由が ADR にあるか)
- [ ] spec.md の接続表・ピン割当と回路図が過不足なく一致しているか
- [ ] ブロック間ネットのラベル名が spec.md「境界の契約」と完全一致しているか
- [ ] 部品の型番・定数がすべて parts.md にあり、一致しているか（推測部品・推測定数が無いか）
- [ ] 未接続ピンに NC フラグが明示されているか（ERC 抑制で隠していないか）
- [ ] 電源系統: 各 IC の電源ピンにデカップリングコンデンサがあるか（spec の指定どおりか）
- [ ] 出図した PDF を目視し、シンボルの重なり・未結線に見える箇所・文字化けが無いか
- [ ] リファレンス指定子に重複・欠番の混乱が無いか

## 2. ライブラリ（シンボル / フットプリント）

- [ ] 使用シンボル・フットプリントがすべてプロジェクトローカル（`hardware/<board>/lib/`）にコミットされているか
- [ ] `sym-lib-table` / `fp-lib-table` が相対パス（`${KIPRJMOD}`）か
- [ ] 新規シンボルのピン番号・ピン名・ピンタイプがデータシートと一致しているか（突合結果を PR に添付）
- [ ] **新規・変更フットプリントの寸法をデータシートの推奨ランドパターンと照合したか（寸法突合表を PR に添付。人間承認必須）**
- [ ] 1番ピンマーク・極性マークがシルクにあるか

## 3. レイアウト PR

- [ ] DRC 警告ゼロか（抑制した項目は理由が ADR にあるか）
- [ ] 回路図とのネット・フットプリント不一致が無いか（DRC のパリティチェック）
- [ ] 承認済みの配置方針（フロアプラン md）どおりか。逸脱は ADR にあるか
- [ ] 基板外形・取付穴・コネクタ位置が要求仕様（plan.md）と一致しているか
- [ ] 出図 PDF / 3D レンダを目視し、シルクの重なり・部品干渉が無いか
- [ ] 発熱部品・ノイズ源と敏感な回路の距離が配置方針どおりか

## 4. 発注前（最終ゲート。人間と一緒に通す）

- [ ] ガーバーをガーバービューア（GUI）で人間が目視したか（KiCad 内部表示だけで済ませない）
- [ ] ドリルファイル・基板外形がガーバーに含まれているか
- [ ] 層構成・板厚・銅箔厚・表面処理・レジスト色の発注仕様が plan.md の指定と一致しているか
- [ ] 主要部品（特にコネクタ・IC）のフットプリントを最終確認したか（§2 の突合表を再確認）
- [ ] BOM の全行に MPN があり、入手性（在庫・代替品）を確認したか
- [ ] 実装（アセンブリ）まで発注する場合、座標ファイル（pos）と BOM のリファレンスが一致しているか
- [ ] 発注するリビジョンの git タグを打ち、製造データ一式が CI で再現生成できるか

## 5. 引き継ぎ

- [ ] progress.md を更新したか（現工程・対象基板・合意状態・未解決事項）
- [ ] ユーザーに、変更点・判断した点・確認してほしい点（特に人間承認が必要なフットプリント）を添えて報告したか
