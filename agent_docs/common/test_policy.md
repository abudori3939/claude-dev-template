# テスト方針（スタック非依存）

CLAUDE.md「品質維持・技術的負債対策」の補足。**テストをどこに置くか／いつ消すか**を定める。
具体的なテストコマンドはスタックガイド（`agent_docs/stacks/<該当>.md`）に従う。

> **用語**: 本ドキュメントで**「境界」**と書いたら **seam（テストを置く公開インターフェース）**を指す。入力の端の値は**「境界値」**と呼び分ける（`coding_standards.md`）。

## テストは境界（seam）に置く

- **テストを書く前に、どの境界でテストするかをユーザーと合意する。** 合意していない境界にテストを書かない。
- 境界＝ `spec.md` の**層1**（システム全体の入出力・モジュール間インターフェース）。**内部関数は境界の後ろに隠す。**
- 理由: 内部にテストを置くと、振る舞いを変えていなくても実装を変えただけでテストが壊れる。境界に置けば、**少ないテストで振る舞いを守れ、リファクタで壊れない**。

## 避けるべきテスト

- **実装結合**: 内部の協力オブジェクトをモックする／private を直接叩く／公開出力ではなく副作用（DB を直接読む等）で確認する。
  見分け方: **振る舞いを変えていないのにリファクタでテストが壊れたら、これ。**
- **トートロジー**: 期待値を実装と同じ手順で計算している（`add(a, b)` の期待値を `a + b` で作る等）。常に通り、コードと食い違えない。
  期待値は**独立した出典**（既知の実測値・手計算・仕様書の例）から取る。
- **水平スライス**: テストを全部先に書いてから実装する。想像上の振る舞いを検証することになり、実装から学んだことを反映できない。
  **1テスト → 1実装**の縦スライスで進める（`plan.md`「フェーズ粒度の方針」）。

## モックは外部境界だけ

外部 API・DB・時刻・乱数・ファイル I/O・実機。**自分が書いたモジュールはモックしない**（モックしたくなったら、テスト可能な設計に直す方を選ぶ）。

## 壊れたテストの扱い（テストを増やし続けない）

> **境界が変わったなら直す。内部が変わっただけなら消す。**

- 実装に結合したテストは負債であり、**削除は後退ではない**。消したら理由を PR に1行書く。
- **PoC モードではカバレッジを門にしない**（`agent_docs/project/plan.md`「開発モード」）。カバレッジを門にすると上の削除ができなくなり、テストが単調増加して CI が PoC の速度を殺す。
