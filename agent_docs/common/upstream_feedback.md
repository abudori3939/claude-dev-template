# 知見の還元（派生プロジェクト → テンプレート）

このリポジトリは **Claude Code 開発ルールテンプレート**（claude-dev-template）から作られている。
テンプレート由来の資産を派生プロジェクトで直したら、**テンプレートへ PR で還元する**。
還元しないと、同じ不具合を次のプロジェクトが必ず踏み直す。

## 何がテンプレート資産か

| 場所 | 扱い | 直したら |
|---|---|---|
| `agent_docs/common/` | テンプレート資産（スタック非依存の作法） | **還元する** |
| `agent_docs/stacks/` | テンプレート資産（スタック固有の作法・共通スクリプト） | **還元する** |
| `agent_docs/project/` | このプロジェクト固有（plan / spec / progress / adr） | 還元しない |
| `CLAUDE.md` のプロジェクト概要 | このプロジェクト固有 | 還元しない |
| `CLAUDE.md` の開発フロー | テンプレート資産 | **還元する** |

判断に迷ったら「**次に作る別のプロジェクトでも同じことが起きるか**」で決める。
起きるなら汎用の知見なので還元、このプロジェクトの事情なら ADR に残して還元しない。

## 還元しないもの（混入させない）

- 部品の型番・入手先コード・回路定数・エラッタの具体値
- プロジェクト固有の生成スクリプト（そのプロジェクトのデータを埋め込んだもの）
- リファレンス指定子・基板名・ディレクトリ名などの固有名

これらは ADR（`agent_docs/project/adr/`）に記録する。**テンプレートには汎用パターンだけを載せる。**

## 手順

1. **溜める**: 派生プロジェクトで作業中に気づいた不具合・改善は、その場でテンプレートを直しに行かず、
   ADR かメモに「テンプレートへ還元する」と印を付けて溜める（作業の集中を切らさない）。
2. **区切りで還元する**: 機能・フェーズの区切りで、溜めた項目をまとめて還元する。
3. **テンプレート側で作業する**: テンプレートのローカルクローンで **`git pull` してから**作業ブランチを切る
   （クローンが古いまま作業して衝突する事故が起きやすい）。
4. **移植する**: ファイルを丸ごとコピーせず、**差分を目視で理解して移植**する。
   派生プロジェクトがテンプレートの最新版より前で分岐している場合、**丸ごとコピーはテンプレート側の改善を巻き戻す**。
5. **固有値を除去する**: 移植したファイルを `grep` して、固有名・ADR 番号・PR 番号・プロジェクト名が
   残っていないか確認する。
6. **検証する**: スクリプトを還元したなら、テンプレートリポジトリ自身に対して実行して動くことを確認する。
7. **実証リンク付きで PR を出す**: PR 本文に、その知見が**どこで実証されたか**（派生プロジェクトの PR / ADR）を書く。
   「机上の改善案」と「実際に踏んで直した」を読み手が区別できるようにする。
8. **差分を確認する**: マージ後、派生プロジェクト側とテンプレート側に差分が残っていないか diff で確認する。
   残っていれば、どちらかが古い（次の還元で潰す）。

## PR 本文に書くこと

- **背景**: 何が起きたか（症状・どのフェーズで踏んだか）
- **変更点**: 種別（バグ修正 / 改善）ごとに一覧
- **実証リンク**: 派生プロジェクトの PR・ADR
- **検証**: テンプレート側で何を確認したか
- **判断が必要な点**: 検証しきれていない箇所は正直に書き、ユーザーの判断を仰ぐ

> テンプレートのマージはユーザーの判断で行う（レビュー無しに自分でマージしない）。
